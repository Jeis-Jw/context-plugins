## 결정

Context Plugins의 상태는 기획, source·contract 구현, deterministic 검증, 실제 host·consumer 운영 검증, remote·marketplace 배포를 분리해 판정한다. SSOT·README·test 통과만으로 live install이나 장기 대화의 recall/capture 품질을 완료로 승격하지 않는다. 배포 주장은 exact remote SHA·catalog parity·설치 좌표·consumer flow를 현재 증거로 확인한 범위에서만 한다.

## 취지

static contract와 local fixture는 제품 의도와 deterministic 동작을 증명하지만 host inventory, 설치 scope, reload, 실제 corpus precision, OS 차이와 publication 상태를 대신하지 못한다. 증거 단계를 분리해야 미검증 영역을 완료로 오판하지 않는다.

## 반려대안

- SSOT를 정본으로 선언했으므로 구현·운영 준비가 완료됐다고 보는 방식은 정본 주장을 독립 증거로 오용해 반려한다.
- local test green을 live host 동작과 marketplace 배포의 증거로 사용하는 방식은 실행 환경과 외부 상태를 검증하지 않아 반려한다.
- 과거 설치된 jeis-ai-plugins 좌표를 새 context-plugins 좌표 활성화로 간주하는 방식은 distribution identity가 달라 반려한다.

## 트레이드오프

- release 보고가 더 세분화되고 미확인 항목을 명시해야 한다.
- 실제 장기 대화의 recall precision·capture 피로도·cross-host portability는 별도 계측 비용이 든다.

## 재평가 조건

- CI와 host integration harness가 remote publication부터 consumer flow까지 반복 가능한 단일 증거를 제공하면 판정 단계를 자동 집계할 수 있다.
