## 관찰

context/decision의 DEC 8개 취지를 계층화하면 핵심 4, 횡단 제약 1, 보조 13, 저장소 운영 1로 정리된다.
핵심 — K1 선택: 기억의 가치는 대화 전체가 아니라 판단을 바꾸는 맥락·근거·결정 연속성 보존이다. K2 정본: 정본은 사람이 검토·공유·버전관리하는 repository 안 Git/Markdown 본문이다. K3 권위: SNAP staging, OBS evidence, DEC choice의 권위 차이를 구분한다. K4 신뢰: 기록과 환경 변경은 사용자 승인을 우회하지 않으며 본 것과 저장된 것이 일치한다.
횡단 — X 비례 금지: recall·capture 비용은 corpus 크기, addon 수, turn 수에 비례해 증가하지 않는다. 집행: index-first recall, 단일 audit와 addon 재판독 금지, signal 없으면 침묵, bounded recall, local-first.
보조 — K1: durable 판정은 미래 재사용성·번복 비용·현재 상태 영향 / transcript·vector archive 비저장 / 조직 기능은 PCMS 책임. K2: 본문만 정본이고 index는 projection / immutable ID와 filename 분리 / 의미 판정은 actual body·scope·rationale. K3: 공통 상태 모델 강제 금지 / claim은 successor supersede로만 인수 / 오래됨은 반증이 아니고 자동 승격·자동 retire 금지 / core는 domain schema 비내장, semantic owner addon으로 확장. K4: write는 exact approval digest bundle 한정이고 fail-closed는 write 경계에만, 검색 drift는 warning / 발견·의미 판정·승인·physical write 분리(core sole-writer, owner complete draft) / 설치·scope·migration 비자동.
운영(제품 취지 아님) — R1: 구현, deterministic 검증, 실제 host/consumer 운영 검증, 배포는 별도 증거로 판정한다.
